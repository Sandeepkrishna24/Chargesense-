2. STRICT STATE OWNERSHIP
────────────────────────
- All app state must belong to the current logged-in user only.
- When user logs out:
  - Clear vehicle selection
  - Clear charging sessions
  - Clear analytics
  - Clear profile data
- No cross-user or residual state is allowed.

────────────────────────
4. MAP AS A CORE FEATURE (NOT A PREVIEW)
────────────────────────
- Map must be a first-class screen, not a visual add-on.
- Map must:
  - Respect range filter
  - Respect charger compatibility
  - Highlight selected station
- Map must NEVER show stations that are invalid for the user.

────────────────────────
5. VEHICLE → EVERYTHING DEPENDENCY
────────────────────────
- Selected vehicle must control:
  - Charger compatibility
  - Charging speed
  - Estimated time
  - Recommendations
- Changing vehicle must immediately recompute all results.
- No stale data is allowed after vehicle change.

────────────────────────
6. RANGE IS A HARD CONSTRAINT
────────────────────────
- User-entered range (km) is a strict boundary.
- Stations outside this range must:
  - Not appear in lists
  - Not appear on map
- Range must be visually obvious (circle, label, distance text).

────────────────────────
9. PERFORMANCE & SCALABILITY MINDSET
────────────────────────
- Vehicle list must remain fast even with 100+ models.
- Filters and search must not re-render unnecessarily.
- App must feel smooth on low-end devices.

────────────────────────
FINAL PRODUCT RULE
────────────────────────
ChargeSense must feel like:
- A tool someone depends on daily
- Predictable
- Honest
- Calm
- Never misleading

If data is not real, do not show it.
If an action is possible, make it obvious.
If an action is not possible, explain why.
